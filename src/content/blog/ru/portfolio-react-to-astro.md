Первая версия этого портфолио была SPA на React 18 + Vite. Она работала, но
каждый визит отдавал посетителю роутер, библиотеку анимаций и полный клиентский
рантайм раньше, чем появился первый абзац текста. Для сайта, чья главная задача —
*показывать* контент, это был неверный выбор.

## Почему Astro

Astro переворачивает дефолт: **сначала HTML, JavaScript — только по запросу**.
Навигация, типографика, страницы статей и большинство секций теперь рендерятся
во время сборки и стоят ноль килобайт JavaScript.

- **Статика прежде всего** — страница целиком генерируется на `astro build`,
  первый экран не ждёт ответа от API.
- **Острова там, где нужна интерактивность** — поиск и фильтры проектов, кнопка
  «Обновить данные GitHub» весят несколько килобайт.
- **Коллекции контента** — статьи лежат обычными Markdown-файлами со строгой
  типизацией frontmatter, а не в ручном массиве TypeScript.
- **Tailwind CSS 4** — конфигурация через CSS-токены, поэтому светлая тема это
  переопределение тех же переменных, а не второй набор классов.

## Что осталось прежним

GitHub-интеграция не переписывалась с нуля: сервисный слой
(`профиль → репозитории → языки + манифесты → анализ`) тот же самый код, он
просто теперь выполняется при сборке, а не при каждом визите.

Лимиты запросов, кэширование и отдача устаревших данных при ошибках остались —
они просто переехали из `localStorage` в небольшой дисковый кэш сборки.

## Честные компромиссы

Новые репозитории появляются на сайте при деплое, а не в ту же секунду, когда я
запушил репозиторий. Кнопка **Refresh** в разделе проектов по-прежнему умеет
подтягивать живые данные, так что между деплоями сайт остаётся актуальным.
