Портфолио полны выдуманных кейсов. Это — нет: список проектов, чипы стека,
статистика языков и строка «Избранное» берутся из публичных данных GitHub.

## Конвейер

```
/users/JengasAdmin             → профиль (аватар, счётчики)
/users/JengasAdmin/repos       → репозитории (форки отбрасываются)
/repos/…/languages             → байты по языкам
/repos/…/contents/             → файлы корня: манифесты, .github/, README
/repos/…/contents/package.json → зависимости → фреймворки и библиотеки
```

Из этих пяти запросов сайт получает для каждого репозитория:

1. **Категорию** — `frontend`, `backend`, `fullstack`, `python` или `other`,
   определяемую по зависимостям и языкам.
2. **Чипы стека** — только библиотеки, которые реально есть в `package.json`.
3. **Инструменты** — только наблюдаемые: папка `.github/workflows` означает
   GitHub Actions. Ничего не угадывается.
4. **Featured-скор** — прозрачная формула: описание, README, темы, ссылка на демо,
   звёзды, форки, размер, свежесть. Она измеряет *сколько информации показывает
   GitHub*, а не качество кода.

## Кэш и лимиты запросов

Неавторизованный GitHub API отдаёт 60 запросов в час на IP. Сайт защищается
тремя уровнями:

- **при сборке** дисковый кэш (`.cache/github.json`) держит снимок свежим
  10 минут и пригодным до недели;
- **в браузере** ответы кэшируются в `localStorage` с индивидуальным TTL;
- **при лимите** отдаётся устаревший кэш вместо пустой страницы, и интерфейс
  честно об этом сообщает.

## Чего здесь намеренно нет

Закреплённые репозитории и карта вклада требуют GraphQL API GitHub, которому
нужна авторизация. Вместо подделки показываю реальные числа: звёзды, форки,
подписчиков и дату последнего пула каждого репозитория.
